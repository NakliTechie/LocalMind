# LocalMind — Code Tier — Agent Handoff

*The model side. Under RLM, LocalMind's job is smaller than it was: one tool, one
kernel, and the discipline to program over its own context.*

**Status:** milestone on the existing LocalMind repo. **Not a new project.**
**Depends on:** Kiln K0–K5, Rig C1/C4/C7.
**Sits alongside:** Forge, the human shell over the same registry. LocalMind is the
brain; Forge is the bench; Kiln is the hands.

---

## 1. What changed with D10

The agent no longer receives a tool schema. **It receives one tool: the Kiln kernel.**

```
before (a):  model → 11 JSON tool schemas → validation → repair → retry → Rig
after  (b):  model → Python cell → rig.patch(...) → Rig
```

Everything downstream of that is deleted work: schema strictness, malformed-call
repair, per-tool retry policy. What replaces it is smaller and better aimed — Bonsai's
weakest published category is agentic tool use; its strongest are reasoning and code.
We move the failure mode onto the axis where the model is strong.

**The `rig` bindings are generated by Kiln from the Rig registry.** LocalMind never
hand-maintains a tool list, and never calls `naklios.fs` directly.

**What the kernel can and cannot reach.** It can run anything in its own namespace
(`rig.run`, `trust: none`) — the red→green loop is the product and blocking it would
be debugging blind. It can push to `agent/<goalId>-<n>` branches so CI can see the
work. It **cannot** read `verificationCommand`, cannot write `status: done`, cannot
push to a default or protected ref, cannot force-push, and cannot refine the base
prompt, the verification command, or the grant. The fence is around the verdict, not
around the work.

---

## 2. The 27B tier

PrismML publishes a `Bonsai ONNX` collection and demonstrates 27B-class inference
in-browser on WebGPU themselves. **Ride their build. Do not write WGSL kernels.** A
build that will not load is a standing interrupt, not an invitation to port anything.

| Variant | Size | Position |
|---|---|---|
| 1-bit Bonsai 27B | ~3.9 GB | **Default 27B tier.** Widest reach |
| Ternary Bonsai 27B | ~5.9 GB | Opt-in quality tier where memory allows |
| Existing 2B / 4B / 8B | ~0.6–2.2 GB | Unchanged defaults |

**Detect, do not configure.** Probe GPU memory and WebGPU limits at load. Offer 27B
only where it will plausibly run; say plainly why when it will not. **Never
surprise-download gigabytes** — show the size, ask, cache. Note the memory budget is
shared with Kiln's Worker; account for both before offering a tier.

## 3. Context as a variable

The binding constraint is an 8–16K usable window against a real repo. RLM turns that
from a ceiling into a programming problem. Three mechanisms, all required:

1. **History is callable, not pasted.** `history.search(...)`, `history.get(n)` page
   from Crate (Kiln K-D3). A long session never has to fit in RAM, let alone in the
   prompt.
2. **Repo map, not repo dump.** `rig_map` (D5 — a Rig command, shared) builds a
   compact structural map: paths, symbols, signatures. Full files open on demand.
   **Never put a tree walk into context.**
3. **Subagents are function calls.** `sub("explore the auth module")` returns a
   string. The child's working context is discarded; only its result survives.
   Concurrency cap 3, depth cap 2, grant inherited and never widened.

**Windup** is the fourth mechanism, ported from ntkit without its ceremony. Under
pressure — tab lifecycle, context threshold, budget fraction — write the session
entry: closing work state (**derived from evidence, never asserted**), the unfinished
item, what shipped, what was verified, decisions taken, and what was tried and
deliberately rolled back. Anything consciously deferred goes to `pending.parked` —
a "not now" that evaporates is how a loop rediscovers the same dead end three sessions
later.

**Resume is automatic.** Attach, reconstruct, state what was picked up in the
transcript, continue. No pause and no question — the operator is reading, not
gating. Only three things halt: the goal is `blocked`, a consistency check failed, or
a staged proposal is awaiting accept.

**Compaction** still runs on a threshold, into a fixed-shape block: goal · files
touched · what was tried · what failed · open question. **The tried-trail must survive
compaction** — it is what stops the loop circling.

## 4. Loop shape

```
operator states a goal + grants a path prefix
      │
      ▼
map ──► plan ──► write Python cell ──► kernel executes ──► verify (fresh kernel)
                       ▲                                        │
                       └──────────── non-zero ◄─────────────────┘
                                                                │ exit 0
                                                                ▼
                                            staged diff ──► operator accepts ──► commit
```

The verdict comes from a **fresh Kiln kernel running the operator's immutable
verification command**. Not from the working namespace, and never from the model's
self-report. Done is the verifier's word, and the substrate enforces it.

---

## 5. Goal attachment

Rig owns the record (C7, at `sys/rig/goals/`) — not Forge, not Kiln. LocalMind
attaches and respects its rules:

- Read on attach; carry `revision` on every write. Stale revision is a rejection, not
  a retry-until-it-works.
- Inherit `grantPrefix` exactly. **Never widen it**, even if the operator's own
  session holds more.
- Append to `triedTrail` on every failed attempt — the signal, not a summary of it.
- Respect the budget. Exhaustion sets `blocked` and stops.
- **The model may not write `status: done`, and cannot read `verificationCommand`.**
- Detaching cleanly on tab close is normal behaviour, not an error path.

---

## 6. Refinement — self-applying, fenced

`refine()` applies during the run. LocalMind's job is to produce refinements worth
keeping — memories about this repo, skill descriptions, subagent briefs — attach the
evidence that motivated each, and let Forge's refine tray show them with one-click
rollback. Review is after the fact, not before.

The Factorio lesson is handled structurally rather than procedurally: their agent
found it could bypass the rules through RCON, and the same loop that had been building
legitimate skills turned to building efficient cheating skills. A self-modifying
harness with a *weak verifier* optimises the verifier. Ours cannot name, wrap, shadow,
or read the verifier, and cannot touch the base prompt or the grant. Everything else
it may rewrite freely.

**Runaway guard.** More than five refinements of one kind within a goal sets it to
`blocked`. A loop spending its turns rewriting itself instead of the code has stopped
making progress, and the no-progress exit applies to refinement too.

---

## 7. Sidecar posture

LocalMind is model-driven and the model is its engine; this milestone does not pretend
otherwise. What matters is that **the artifacts are deterministic** — files, commits,
and test results replay a year later with no model, no network, and no LocalMind. The
AI authored them; it is not load-bearing for reproducing them.

Rig, Kiln, and Forge underneath stand entirely without any model. A person can open
Forge, write Python in the kernel, run their tests, and commit. That is where the
removability guarantee lives, and it is why letting a small local model write into a
real repo is safe rather than reckless.

## 8. Chunks and checkpoints

| Chunk | Content | Checkpoint |
|---|---|---|
| **L0** | Kernel as sole tool; grant flow; staged-diff rendering; cell provenance | Model completes a scripted three-step task by writing Python; every op appears in the op-log under the session identity; nothing committed without an accept |
| **L1** | 27B tier: load, memory probe (accounting for Kiln), capability gating, download consent | Loads and generates on floor hardware; below-threshold hardware offered the smaller tier with an honest message and no error wall |
| **L2** | Repo map, callable history, subagents, compaction | Golden fixture: agent takes a seeded failing test to green with no operator intervention, budget-capped. Assert the green result **and** that no test was skipped or deleted **and** that the verdict came from the fresh kernel |
| **L3** | Cell reliability: syntax-error recovery, exception handling, no-progress detection | Cell success rate over a fixed 50-cell harness; regression threshold recorded as the gate. A repeated identical failure triggers the no-progress exit, asserted |
| **L4** | Goal attachment: attach, revision handling, trail append, budget, detach | Kill tab mid-goal → reopen → re-attaches at the same step; stale-revision write rejected; `done` forgery rejected; `verificationCommand` read attempt rejected |
| **L5** | Self-applying refinement with evidence | Applies and snapshots; evidence attached and readable; a refinement naming or shadowing verification, the base prompt, or the grant is rejected; runaway guard fires at five |
| **L6** | Windup + automatic resume | A simulated `freeze` mid-task writes a session entry with `closingWorkState: building` and the unfinished item named; the next session **resumes and continues with no operator input**, stating what it picked up; a deliberately reversed change lands in `rolledBack[]`, not `triedTrail[]`, and is not re-attempted |

## 9. Hard rules

1. **Do not write WGSL kernels or port a model format.** Ride the published build.
2. **Do not hand-maintain a tool list.** Kiln generates bindings from the registry.
3. **Do not call `naklios.fs` directly** or bypass the path grant.
4. **Do not auto-commit.** Push is available but only to `agent/<goalId>-<n>`
   branches — never a default or protected ref, never with force.
5. **Do not let the model self-report success.** The exit code is the signal.
6. **Do not let the model write `status: done`** or read `verificationCommand`.
7. **Do not widen an inherited grant**, in a session or a subagent.
8. **Do not refine the base prompt, the verification command, or the grant.**
9. **Do not skip or delete a test to reach green.** Named reward hack; hard fail.
10. **Do not download a multi-gigabyte model without asking.**
11. **Do not break the no-model path.**
12. **Do not add Mach-1** or any model without a published browser build.

## 11. What this proves if it lands

A 27B-class model, on the user's own hardware, writing Python against a kernel that
can only see one granted folder, editing a real git repository in the user's own
storage, judged by an exit code from a kernel it cannot reach — with no server, no
account, no API key, and no telemetry anywhere in the loop. And a goal that survives
closing the laptop.

Prime Agent proved the architecture works, on a daemon with a frontier model and an
explicit not-a-sandbox warning. Standard Code sells the same capability as a cloud
session billed per line. This is the third answer: the same architecture, structurally
sandboxed, on the user's own machine, with a model small enough to fit in a tab.
